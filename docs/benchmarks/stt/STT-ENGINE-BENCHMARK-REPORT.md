## 1. Objective

Execute a reproducible real-world benchmark of the recognised STT candidates
(`faster_whisper`, `vosk`) on representative real radio audio from the actual
TACTICAL_CORE audio pipeline, to create objective evidence for a later
architecture decision. This WO does **not** select or authorize a production
engine.

## 2. Dataset description

The only WAV masters available on this host are the recordings the actual
project pipeline (RTP → VAD → WAV master → STT seam) wrote to the archive root.
On this host they are located under:

```text
/tmp/tmp830mejt0/2026/09/02/radio/
/tmp/hv_nw8kok3b/2026/09/02/radio/
/tmp/aud_a03080ty/2026/09/02/radio/
```

Provenance (established by inspecting `backend/app/audio/rtp_simulator.py` and
`backend/tests/test_wo039b_recording.py`): these are **WO-039-B/C unit-test
fixtures**. They were produced by feeding a constant-amplitude PCM value (e.g.
`_pcm(20000)`, a "speech tone" at RMS ~20000 over a silence floor at ~50)
through the real pipeline to exercise the VAD / segmentation / recording logic.

Consequence: they contain **no speech, no words, no callsigns**. Two of the
recordings (`64b8be8b8f77`, `1a9bfad300ef`) have exactly **2 distinct sample
values** — a constant 20000-value tone over a 50-value silence floor. The
remaining recordings have ~250 distinct values, which is the A-law companding
quantization range for a constant/full-scale test value. None of the 36 is a
real radio transmission with linguistic content.

## 4. Ground-truth methodology

WO-040 §5 requires a manually verified reference transcript for every
transmission, with `audio_id / source / timestamp / duration /
reference_transcript / callsigns_present`, never generated by a candidate
engine. **No ground-truth transcripts exist on this host.** There is no
manually verified reference for any recording, and none can be derived honestly:
the recordings contain no words or callsigns to transcribe. `dataset_manifest.csv`
records `ground_truth=""` for every row. A deterministic WAV → reference
transcript mapping cannot be established.

## 5. Audio normalization

All 36 masters are project-native: mono, 16-bit PCM, 8 kHz (this is exactly the
format the WO-039-C3 worker validates and the format produced by the G.711
A-law decode path). Since no engine inference ran, no per-candidate
normalization was applied. A normalization step, if the benchmark were
executable, would resample everything to a single documented format; this is
moot here because no engine ran.

## 25. Limitations

The benchmark could not be executed. The limitations, each independently
sufficient to block a valid benchmark:

1. **Offline candidate runtime/model absent (WO-040 §8).** Neither `faster_whisper`
   nor `vosk` is installed, and no STT model exists on disk. The WO requires all
   models and runtime components to already exist locally and prohibits
   downloading them for the benchmark. This is the documented technical
   inability to execute the benchmark for either candidate.
2. **No ground truth (WO-040 §5).** No manually verified reference transcript
   exists for any recording.
3. **Dataset is not real radio (ADR-014; WO-040 §2/§4).** All 36 available WAV
   masters are WO-039 unit-test fixtures (constant-amplitude test tones), not
   real radio transmissions. ADR-014 states that synthetic speech alone is not
   acceptable.
4. **Dataset size below the mandatory minimum.** 36 < 50 required transmissions,
   and 0 of the 36 are real radio.

## 26. Recommendation

Do **not** select either candidate. Do **not** authorize a production STT
engine. The engine-selection gate is not satisfied. Before any selection can be
considered, the following must be true:

- a candidate runtime and model are provisioned locally (offline);
- a dataset of **≥50 real radio transmissions** produced by the actual project
  pipeline is collected, each with a manually verified reference transcript and
  callsigns;
- the benchmark is run identically for both candidates (same dataset, language,
  normalized audio, hardware), recording cold-start and warm inference
  separately;
- all metrics (WER, CER, callsign accuracy, latency, RTF, CPU/RAM/GPU/VRAM,
  failures, timeouts) are measured and recorded;
- the mandatory gate is assessed and, if passed, the engine-selection decision
  is accepted by the Chief Systems Architect.
